# Migration Jobs to CAP Native Event Queues (v2 Review)

This change refactors tenant onboarding and discovery from a custom outbox pattern to CAP's built-in transactional event queues. The implementation correctly uses `cds.queued(this).emit()` for both TenantService (DiscoveryRequested events) and DiscoveryService (AssessmentRequested events). Custom outbox infrastructure was removed, and package.json now configures the persistent outbox explicitly.

**Watch for:** console.log statements still scattered across srv/ files despite the "use cds.log() everywhere" requirement (confirmed, 30+ occurrences).

**Verdict**: NEEDS_CHANGES

---

## High-level view

The core CAP native queue refactoring is complete. TenantService emits `DiscoveryRequested` events via `cds.queued(this)` in both `submitProfile` and `triggerDiscovery`, with a properly structured event handler that re-throws errors for CAP's retry mechanism. DiscoveryService now handles `AssessmentRequested` events the same way for async artifact assessment.

The package.json configures `cds.requires.outbox` with explicit maxAttempts (10), chunkSize (100), and parallelism (5). Server.js is clean — no custom outbox initialization, just logging the queue config on startup for observability.

The console.log cleanup from the original requirements was only partially applied. The four files mentioned in the prior review (vectorStore.js, rap-dev-orchestrator-service_impl.js, simple-server.js, destinationService.js) may have been fixed, but 30+ console.log calls remain in brain-service.js, pipoSoapClient.js, pipoClientImproved.js, document-service.js, rap-dev-orchestrator-service.js, adtMcpClient.js, and vectorSearch.js.
